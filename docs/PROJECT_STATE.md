## Current service-size increment

The existing measured-limit UI records a smallest/largest size plus explicit observed
and source dimension meanings. No size is inferred from a service label, quantity or
bundle. Only recorded individual outside diameters are compared with pinned min/max
limits; nominal/rectangular/bundle/unknown meanings stay unresolved. The range covers
recorded observations only. Source interpretation, instance count/coverage and full
compatibility remain unapproved/unassessed. Scope and canonical physical rows are unchanged.

Additive `CLASSIFIRE-DRAFT-SYSTEM-MATCH-v3` retains the existing revision model.
V1/v2 bytes stay readable; an old-form save against v3 cannot silently discard size
claims. Keep/reject preserves the complete review. Explicit Estimate creation retains
the exact v3 match; scope-and-system PDF/XLSX show its range, meanings and checks.
No migration, dependency, agent, provider or canonical authority was added.
See [the contract](./DRAFT_SERVICE_SIZE_REVIEW.md).
